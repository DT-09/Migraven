METHOD / COMPARISON SEMANTICS

Every result has
a defined meaning.

Migraven keeps its comparison model explicit. It does not quietly normalize values or infer that a mismatch is a defect.

STATUSMEANINGREVIEW ACTION
PASSPaired key; selected field values are exactly equal.Record the check as matching within this narrow scope.
FAILPaired key; selected field values differ.Inspect both values and determine whether the difference is expected.
INDETERMINATEKey exists in only one dataset.Investigate extraction scope, timing, mapping or missing-record causes.
THE RULES

Specific by design.

01

Unique key required.
Keys must be non-empty and unique in both datasets.

02

Exact string comparison.
10, 10.0 and "10" remain different. No date, numeric or currency normalization is applied.

03

Selected fields only.
Up to 32 selected fields are compared independently. A result says nothing about fields not selected.

04

Original row references.
Findings retain source-row locations so reviewers can return to the input exports.

05

Unsigned integrity manifest.
SHA-256 hashes detect changes against the recorded manifest. They do not prove who created it or stop the manifest itself being replaced.

EVIDENCE IS NOT AUTHENTICITY

Know what the files
can—and cannot—prove.

A comparison report describes what Migraven observed in the supplied exports under the selected rule. It cannot establish that the exports were complete, correctly extracted, authorized, or semantically equivalent.

For stronger provenance, keep source exports and generated evidence in controlled storage, record who supplied and approved them, and use an organization-approved signing or records process. Migraven's current manifest is an integrity aid, not a digital signature or audit certification.
