# Verity — paid pilot

## Offer

**Migration Export Verification Pilot**

A fixed-scope review of one source export and one target export, using a buyer-approved unique key and up to three agreed critical fields.

## Buyer receives

1. Input inventory: filenames, formats, column names and row counts.
2. Machine-readable comparison outputs generated by Verity.
3. A self-contained HTML evidence report for human review.
4. Exception register listing mismatched, source-only and target-only keys.
5. Source-row references for each finding.
6. A review note separating observed differences from unresolved explanations.
7. A reproducibility note recording the exact command, tool version and agreed rules used.

## Pilot boundaries

- CSV or flat-object JSONL files only.
- One source/target dataset pair.
- One unique key.
- Up to three critical fields.
- Exact string comparison only.
- No live database access, production credentials, or direct system changes.
- No claim that a mismatch is a migration defect until the buyer investigates it.
- No claim that a PASS proves business correctness, transformation correctness, or completeness beyond the configured checks.

The buyer must remove personal, confidential and regulated data before sharing files. Use synthetic or appropriately de-identified data for the first evaluation.

## Acceptance criteria

The pilot is complete when:
- both input files parse successfully or the input limitation is documented;
- the agreed key is present and unique in both datasets;
- each agreed field has a machine-readable result;
- every generated finding includes the relevant source-row reference;
- the buyer can reproduce the run from the recorded command;
- unresolved differences are explicitly listed rather than silently classified.

## Commercial model

1. **Paid pilot:** one dataset pair, one key, up to three fields, a fixed delivery date and a defined evidence pack.
2. **Per-project license:** repeatable use by a migration team for a named migration project.
3. **Team license:** annual use across projects, with version updates and support.
4. **Private deployment / OEM:** separately scoped license and integration support for larger consultancies or software vendors.

These are proposed commercial packages, not validated price points. No public price or embedded billing flow exists yet. Agree scope, fee, delivery date, data-handling terms and payment route with the responsible buyer before receiving data. Do not accept production credentials or data the delivery team is not authorized and equipped to handle.

## Pilot conversation

Ask the migration lead:
1. What source and target systems are being migrated?
2. Which exported datasets and fields are used for sign-off?
3. How are record-level differences found today?
4. What evidence must the client or delivery lead review?
5. Can they test the workflow on synthetic or de-identified exports?
6. Who owns the budget and can approve a paid evaluation?

A paid pilot is justified only if the answers reveal a live, recurring need and an identified budget owner.
